# 実験C（発展）考察ドラフト：Nested CV閾値最適化

補正なしC0条件でF1を最適化した結果、内側CVが選択した確率閾値はLogistic Regressionで平均0.316、校正済みLinear SVCで平均0.298となり、いずれも既定0.5を下回った。外側Foldの平均F1はそれぞれ0.524から0.575、0.527から0.584へ上昇した。

改善はRecall上昇とPrecision低下の交換によって得られた。Logistic RegressionのRecallは0.392から0.528、Linear SVCは0.385から0.541へ上昇した一方、Precisionは0.819から0.642、0.860から0.638へ低下した。誤検知と見逃しのコストが非対称な業務では、F1最大化が最適な意思決定とは限らない。

Fold単位ではLogistic Regressionが5/5 FoldでF1改善、Linear SVCは4/5 Foldで改善し1 Foldで0.011低下した。閾値を外側testで調整すればこの悪化を後知恵で回避できるが、それは評価リークとなる。本実験のNested CVは、実運用で未知データへ適用した際に生じる閾値選択の不確実性を保持している。

## 実務的示唆

- 閾値最適化の目的関数を実行前に固定し、外側testや本番結果で後から調整しない。
- Linear SVCのスコアを確率として扱う場合は、学習範囲内だけで校正する。
- 閾値非依存のAverage Precisionと、閾値依存のRecall・Precision・F1を分けて管理する。
- クラス比率や損失構造が変化した場合は、固定閾値を永久利用せず再校正・再選択する。
