# 実験D：日本語テキスト分類 Before（IPA辞書）/ After（neologdn + Sudachi）比較の定量的考察

対象データ: livedoor News Corpus（9クラス、ダウンロード直後7,367記事、`raw_text`完全一致重複6件を除去し7,361記事で評価。正例/負例ではなく9クラス分類）。
Before: クレンジングなし＋MeCab（IPA辞書）形態素解析＋TF-IDF。After: `neologdn`正規化＋Sudachi（Mode C, core辞書）形態素解析＋TF-IDF。
TF-IDFは各Foldの学習データのみでfitするPipeline構成であり、クレンジング有無・形態素解析器・辞書が同時に変わるため、以下は個別手法の効果ではなく前処理パイプライン全体（Before/After）の比較として解釈する。

参照ファイル: `expD_metrics_summary.csv`, `expD_metrics_summary_agg.csv`, `expD_paired_fold_diff.csv`,
`expD_token_stats.csv`, `expD_vocab_size.csv`, `expD_metadata_leak_check.csv`, `expD_preprocessing_time.csv`,
`expD_coefficients.csv`, `expD_feature_importance.csv`, `expD_param_tuning.png`

---

## 第1章: メタデータリークの検出と排除

### 【事実】

コーパス読込直後（footer除去処理を実装する前）に、各カテゴリの記事本文にカテゴリ自身の英字ディレクトリ名が literal に出現する件数を調べたところ、`smax`カテゴリでは870件中861件（**98.9%**）に自社媒体名「エスマックス（S-MAX）」ないし`smax`という文字列が本文中に含まれていた。原因を特定すると、各記事本文の末尾に「■関連リンク」という見出しに続く関連記事・関連サイトへのリンク一覧が付与されており、そこに「エスマックス（S-MAX）」という媒体名が記載されていた。

`src/experiments/preprocessing.py`の`_strip_footer`関数で、本文中に最初に出現する「■関連リンク」または「■関連記事」以降の文字列を除去する処理を実装し、9カテゴリ全記事に適用した。修正後に同じ検査を再実行した結果は`expD_metadata_leak_check.csv`の通りである。

| category | 自カテゴリ名を含む記事数 |
| :--- | ---: |
| dokujo-tsushin | 0 |
| it-life-hack | 0 |
| kaden-channel | 0 |
| livedoor-homme | 0 |
| movie-enter | 1 |
| peachy | 3 |
| smax | 1 |
| sports-watch | 0 |
| topic-news | 0 |

`smax`は861件→**1件**まで低減した（99.9%除去）。本実験のBefore/After比較・CV評価・説明性分析は、すべてこの修正後のコーパスに対して実施している。

### 【メカニズム・提言】

TF-IDFのような表層語彙ベースの表現では、「smax」という1トークンが特定カテゴリの870件中861件に排他的に出現すれば、そのトークン単独でほぼ完全にクラスを予測できてしまう。これは、モデルがニュース記事の内容（トピック・語彙）を学習しているのではなく、媒体側が機械的に付与した定型フッターを学習している状態であり、実際の運用（未知の記事、あるいは他媒体の記事）に対しては再現しない虚偽の高精度をもたらす。この種のリークはAccuracy・F1のような集計指標だけを見ていては検出できず、**個々のクラスについて「本文中に自分自身のクラス名・媒体名が含まれる記事の割合」を機械的に検査する**ことで初めて発見できる。

提言:
- 日本語テキスト分類においては、収集元媒体のフッター（関連リンク・関連記事・広告・署名）を、クレンジングや形態素解析の前段で除去する処理を**必須**の前処理ステップとして組み込む。
- フッター除去は見出し文字列の完全一致だけに依存せず、除去後も同様のリーク検査（クラス名の literal 出現率）を再実行し、除去漏れがないことを確認する（第4章で後述する通り、本実験でも見出しの異なる残存フォーマットが1件検出されている）。
- Before/After比較のような前処理効果の検証実験では、リーク検査をクレンジング手法の比較よりも先に行う。リークが残ったまま前処理Before/Afterを比較すると、リークによる精度の底上げが両条件に等しく乗り、前処理そのものの効果を覆い隠す。

## 第2章: Before（IPA辞書）vs After（neologdn + Sudachi）の精度比較

### 【事実】

5-Fold CV平均（`expD_metrics_summary_agg.csv`、主指標macro-F1）:

| model | Before macro-F1 | After macro-F1 | Before Accuracy | After Accuracy |
| :--- | ---: | ---: | ---: | ---: |
| knn | 0.7917 | 0.7891 | 0.7989 | 0.7965 |
| linear_svc | **0.9413** | 0.9393 | 0.9453 | 0.9432 |
| logistic_regression | 0.9118 | 0.9094 | 0.9181 | 0.9158 |
| random_forest | 0.8895 | 0.8850 | 0.9069 | 0.9031 |

4モデルすべてでBeforeがAfterをわずかに上回る。Fold単位のペア差（`expD_paired_fold_diff.csv`、macro-F1）は次の通りである。

| model | mean_diff (After−Before) | std_diff | 改善Fold数 | 悪化Fold数 |
| :--- | ---: | ---: | ---: | ---: |
| knn | -0.00260 | 0.00856 | 2 | 3 |
| linear_svc | -0.00206 | 0.00390 | 1 | 4 |
| logistic_regression | -0.00244 | 0.00505 | 1 | 4 |
| random_forest | -0.00459 | 0.00943 | 1 | 4 |

4モデルとも平均差は負（-0.0021〜-0.0046ポイント）であり、5 Fold中3〜4 FoldでAfterがBeforeを下回った。差の標準偏差（0.0039〜0.0094）は平均差そのものと同程度かそれ以上の大きさであり、この差を「Afterが明確に劣る」と断定できるほど大きくはないが、**「Afterが優れている」という仮説を支持する結果でもない**。少なくとも本コーパスにおいては、Before→Afterの精度改善は観測されなかった。

### 【メカニズム】

livedoor News Corpusは新聞社・メディア企業が編集・校正した配信記事であり、SNS投稿のような表記揺れ（半角/全角の混在、連続する感嘆符、顔文字、俗語的な省略表記等）が本来的に少ない。`neologdn`が主に補正する対象（全角・半角の不統一、長音や記号の連続、絵文字混じりの崩れた表記）が入力テキストにほとんど含まれないため、クレンジングによる表記統一の効果が limited になる。

同様に、Sudachi Mode C（長単位分割）はIPA辞書（短単位に近い分割）と比べて複合語をより長い単位でまとめる傾向があるが、これは語彙数を減らす方向にも増やす方向にも働きうる。本実験の実測（第3章）ではむしろ語彙数が増加しており、複合語をより長い単位にまとめることによる語彙圧縮よりも、Sudachi辞書に収録された固有名詞・新語のエントリが未知語のIPA辞書分割（短い断片への分割）を上書きし、結果としてIPA辞書側では出現しなかった表層形が新たに語彙に加わった影響が上回ったと考えられる。すなわち、「表記揺れの吸収による精度向上」という当初の仮説は、少なくとも本コーパスでは前提となる表記揺れの量そのものが少なく、成立しなかったと解釈できる。

### 【改善策・提言】

- 「高度な前処理（neologdn・拡張辞書・長単位分割）を導入すれば必ず精度が向上する」という前提を置かない。前処理の効果はコーパスの性質（表記の乱れの多寡）に強く依存し、正書法が整った校正済みテキストでは効果が乏しい、あるいは無い場合がある。
- 前処理パイプラインを変更する際は、必ず本実験のようなBefore/Afterのアブレーション比較をCVで実施し、「導入する」ことを既定路線とせず、実測データに基づいて採否を判断する。
- 表記の乱れが多いことが想定されるドメイン（SNS投稿、口コミ、チャットログ、OCR結果等）では同様の検証を別途行い、本実験の結論（整形済みニュース記事では効果が乏しい）をそのまま適用しない。ドメインが変われば表記揺れの量も変わるため、再検証が必要である。

## 第3章: 形態素解析コスト・語彙数・トークン長統計の分析

### 【事実】

処理時間（`expD_preprocessing_time.csv`、7,361文書全体）:

| 処理 | 所要時間 |
| :--- | ---: |
| IPA辞書によるMeCab形態素解析（Before） | 6.02秒 |
| neologdn正規化（Afterクレンジング） | 4.08秒 |
| Sudachi Mode C形態素解析（After） | 14.71秒 |
| Afterクレンジング＋形態素解析 合計 | 18.79秒 |

Afterの形態素解析（クレンジング込み）はBeforeの約3.1倍の処理時間を要した（18.79秒 / 6.02秒）。

語彙数（`expD_vocab_size.csv`、`min_df=2, max_df=0.95`、`max_features`上限なしでの生語彙数）:

| condition | 語彙数 |
| :--- | ---: |
| Before（IPA辞書） | 42,123語 |
| After（neologdn + Sudachi） | **46,936語** |

Afterの語彙数はBeforeより4,813語（+11.4%）**多い**。当初想定していた「表記揺れ吸収による語彙圧縮」とは逆方向の結果である。

トークン長統計（`expD_token_stats.csv`）:

| condition | 空文書数 | 最小トークン数 | 中央値トークン数 | 最大トークン数 |
| :--- | ---: | ---: | ---: | ---: |
| Before | 0 | 11 | 541.0 | 6014 |
| After | 0 | 11 | 538.0 | 6061 |

空文書は両条件とも0件。中央値トークン数はBefore 541、After 538とほぼ同水準（-0.6%）である。

### 【メカニズム・提言】

語彙数増加の主因として、Sudachi Mode Cの辞書（SudachiDict-core）がIPA辞書には収録されていない固有名詞・新語・カタカナ複合語のエントリを多数含み、これらが新たな語彙として出現した可能性が高い。一方、neologdnによる表記統一（全角/半角統一、繰り返し記号の圧縮等）は第2章で述べた通り本コーパスでは対象となる乱れが少なく、語彙圧縮への寄与が小さかった。結果として、辞書拡張による語彙の**増加**が、クレンジングによる語彙の**圧縮**を上回った。

処理コストの面では、Afterの形態素解析はBeforeの約3倍の時間を要する一方、第2章で見た通り精度は同等か微減であり、**本コーパス・本タスクに関する限り、処理コストに見合う精度上の便益は確認できなかった**。

軽量前処理（MeCab/IPA辞書、クレンジングなし）の採用判断基準として、以下を提言する。
- 対象コーパスが校正済み・正書法の整った媒体（新聞、公式ニュース配信等）である場合は、まずBefore相当の軽量パイプラインをベースラインとして構築し、拡張辞書・クレンジングの追加はアブレーション比較で効果を確認してから導入する。
- 処理時間が制約になる用途（大量文書のバッチ処理、リアルタイム分類等）では、精度差が誤差範囲内（本実験ではmacro-F1差-0.002〜-0.005、標準偏差と同程度）にとどまる場合、3倍の処理コスト増を正当化する根拠が乏しい。
- 表記揺れが多いドメインに適用する場合は、本コーパスとは前提が異なるため、対象ドメインで同様の語彙数・処理時間・精度のアブレーションを個別に実施する。

## 第4章: モデルの説明性とハイパーパラメータ挙動

### 【事実】代表クラスの上位寄与語（After、`expD_coefficients.csv`）

| クラス | 正方向上位3語 | 負方向上位3語 |
| :--- | :--- | :--- |
| sports-watch | Sports(+4.36), Watch(+4.19), 選手(+3.60) | :(-2.44), !(-1.90), /(-1.67) |
| movie-enter | 映画(+5.32), 』(+4.79), 『(+4.78) | ■(-1.39), 女子(-1.28), さん(-1.17) |
| it-life-hack | ■(+7.22), 孫(+3.00), !(+2.58) | ます(-2.59), "(-1.90), です(-1.71) |

sports-watch・movie-enterの上位語は「Sports」「Watch」「選手」「映画」「』」「『」等、媒体名の一部やトピックを直接反映する語であり、内容に基づく分類として妥当性が高い。

一方、**it-life-hackの正方向1位が記号「■」（係数+7.22）** であり、これは他の全クラスの上位語（最大でも movie-enter の「映画」+5.32）より大幅に大きい値である。`expD_feature_importance.csv`（Random Forest上位10語）にも「■」「』」「『」「【」「】」等の記号が上位に含まれており、内容語（トピックを表す名詞等）と記号が混在している。

実際にコーパスを確認したところ、it-life-hackカテゴリの記事の**96.4%**が本文中に「■」を含む（他カテゴリは5.4%〜46.0%）。これは第1章で除去した「■関連リンク」フッターとは別に、it-life-hack媒体が記事本文そのものの構成（複数の関連トピックを箇条書き的に「■見出し」の形式で並べる記事フォーマット）で「■」を多用していることに由来する。フッター除去（「■関連リンク」「■関連記事」以降の削除）はこの用法を対象にしていないため、本文中に残存している。

### 【メカニズム】

「■」はit-life-hackという媒体の**執筆・編集上のフォーマット習慣**であり、記事の話題内容（IT・ガジェット）そのものを表す語ではない。TF-IDFは表層のトークン出現頻度のみに基づくため、このような書式上の慣習であっても、あるクラスに強く偏って出現すれば、内容語と区別なく強い判別特徴として扱われる。係数+7.22という値は、他クラスの内容語由来の係数（+4〜+5台）を上回っており、モデルがit-life-hackの分類において、内容理解よりもこの書式トークンに依存している可能性を示唆する。

### 【事実】ハイパーパラメータ挙動（`expD_param_tuning.png`、Afterパイプライン、scoring=macro-F1）

Logistic Regressionの`C`: `C=0.01`でTrain=0.634・CV=0.611、`C=0.1`でTrain=0.840・CV=0.815、`C=1`でTrain=0.970・CV=0.910、`C=10`でTrain=1.000・CV=0.937、`C=100`でTrain=1.000・CV=0.939。CVは`C=10`付近でほぼ頭打ちになり、`C=10`→`C=100`の追加改善は+0.002程度にとどまる。Trainは`C=10`で1.000に到達しており、以降Trainスコア上は「完全適合」の状態が続くが、CVスコアはそこから大きく劣化しない。

Random Forestの`max_depth`: `max_depth=3`でTrain=0.720・CV=0.703、`max_depth=5`でTrain=0.803・CV=0.777、`max_depth=10`でTrain=0.891・CV=0.823、`max_depth=20`でTrain=0.990・CV=0.825。Train-CVギャップは深さ3の0.017から深さ20の0.165まで一貫して拡大するが、CVスコア自体は検証した範囲（3〜20）で頭打ちにならず、単調に上昇し続けている。

### 【メカニズム・提言】

Logistic RegressionでTrainが1.0に達しながらCVスコアが大きく崩れない現象は、TF-IDFのような高次元疎表現（本実験では数万語オーダーの語彙）では、学習データが線形分離可能に近い状態になりやすく、正則化を弱めて訓練データに完全適合させても、決定境界の位置自体は検証データに対して大きく崩れないためと考えられる。これは数値データに対する線形モデル（実験Aのbreast cancerデータ等）で見られる過学習の挙動とは異なる、テキスト分類特有の傾向である。

Random Forestは検証範囲内（`max_depth≤20`）でCVスコアの天井に達しておらず、本実験の主要CV評価（第2章、`build_model`のデフォルト設定＝`max_depth=None`＝無制限）が採用している「深さ無制限」という設定は、この上昇傾向と整合的であり、少なくとも`max_depth=20`相当までは妥当な選択と言える。ただし、より深い木・より多い`n_estimators`でCVスコアがどこで頭打ちになるかは本実験のグリッド（3, 5, 10, 20）では特定できていない。

提言:
- Logistic Regressionは`C=10`前後を第一候補とする。`C=100`への追加チューニングの効果は乏しく（+0.002程度）、正則化を極端に弱める必要性は低い。
- Random Forestの`max_depth`は、本実験のグリッドでは天井が見えていないため、`max_depth=None`（デフォルト）に加えて`max_depth=30, 50`等のより広いグリッド、または`n_estimators`の増加を試し、CVスコアが頭打ちになる点を探索することを次の検証課題とする。
- 説明性分析においては、上位寄与語に記号・書式トークン（「■」「』」「『」「】」等）が含まれる場合、それが内容語かフォーマット由来かを個別に確認する。フォーマット由来の語が上位を占めるクラスでは、Permutation ImportanceやFold間の上位語の再現性確認等、追加の検証を行うことが望ましい。

## 第5章: 総括 — 日本語テキスト分類における前処理・リーク対策・コスト評価チェックリスト

- [ ] **媒体・収集元のフッター（関連リンク・関連記事・署名・広告）を前処理の最初期段階で除去する**。除去は見出し文字列の完全一致だけに頼らず、除去後に「本文中に自クラス名が含まれる記事の割合」を機械的に再検査する（本実験ではsmaxで861/870→1/870に低減）。
- [ ] **フッター以外の書式上の慣習（箇条書き記号、装飾記号等）が特定クラスに偏っていないかを、説明性分析（`coef_`・`feature_importances_`）の上位語から確認する**。内容語ではなく記号が異常に高い重みを持つ場合、それは分類の妥当性を損なう可能性がある（本実験ではit-life-hackの「■」が96.4%の記事に出現し、最大の正係数を持っていた）。
- [ ] **「高度な前処理を追加すれば精度が上がる」という前提を置かず、Before/AfterのCVアブレーションで実測する**。本実験では、neologdnクレンジング＋Sudachi Mode C＋拡張辞書の導入によりmacro-F1が4モデル全てでわずかに低下し（-0.002〜-0.005、標準偏差と同程度の小さな差）、語彙数はむしろ11.4%増加した。
- [ ] **形態素解析・クレンジングの処理時間を精度改善分と対比して評価する**。本実験ではAfterの前処理はBeforeの約3倍の時間（18.79秒 vs 6.02秒、7,361文書）を要したが、精度上の便益は確認できなかった。
- [ ] **TF-IDFはPipeline内で各CV Foldの学習データのみにfitし、リークを防止する**。
- [ ] **正則化・木の深さ等のハイパーパラメータは、高次元疎表現特有の挙動（Train=1.0でもCVが大きく崩れない等）を踏まえてチューニングし、単純な「Trainが1.0に近い＝過学習」という判断を機械的に適用しない**。
- [ ] 本実験の結論（Afterの効果が乏しい、語彙数が増加する等）は**livedoor News Corpusという校正済みニュースコーパスに特有の結果**であり、SNS投稿・口コミ・OCRテキスト等、表記の乱れが多いドメインでは同一の検証を再実施したうえで判断する。
